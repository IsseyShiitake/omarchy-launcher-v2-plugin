# Omarchy Launcher v2 — Full Audit Report

**Date:** 2026-10-21 15:58 (Europe/Paris)
**Scope:** `omarchy-launcher-v2` (drop-in pack) and `omarchy-launcher-v2-plugin` (plugin edition)
**Base:** omarchy `821ae589` · Quickshell 0.2.1 · Hyprland 0.56.2 · Fedora 44
**Auditor method:** full read of all 4 810 lines of source + **437 executed tests** (227 in a real
Qt6 QML engine, 146 in Node against the model layer, 42 on the key tree, 14 on the selection
model, plus a live `install.sh`→`uninstall.sh` cycle and a live execution of the generated guard
batch against this machine's real menu). No claim below is taken from a comment or a README —
every one was reproduced.

---

> **Status (later the same day):** every defect below is fixed and verified in
> commit `721e9b1` (plugin edition) and `f648660` (pack edition); the deduplicated
> list is `AUDIT-CONSOLIDATED-2026-10-21.md`. This file is the record of the audit,
> not a list of open issues.

## Verdict

The **implementation is strong**. The feature set the READMEs advertise is genuinely present,
reachable and numerically correct — I recomputed every documented example. The **packaging and
documentation have drifted**: the two editions of this project no longer ship the same code, and
several README claims describe behaviour the code does not have.

**12 confirmed defects**, 4 of them user-visible today, plus one upstream-inherited landmine that
silently deletes menu rows.

---

## Part 1 — Confirmed bugs (ranked by impact)

### B1 · The drop-in pack and the plugin edition ship **different code** — and the pack is slower
`files/MenuModel.js` (plugin) is **62 lines ahead** of what `install.sh` produces. The live
checkout's `MenuModel.js` matches the *plugin* copy, not the *pack* result.

`patches/menu-model-ranking.patch` contains only the 1-line ranking hunk. The parallel-guard work
(`guardPrelude` FD rewrite + `GUARD_GROUPS = 8`) exists in **no patch and in no `files/`** of the
pack.

Measured on this machine, real menu, 7 runs each:

| route | guard batch (median) | min | max |
|---|---|---|---|
| drop-in pack (`install.sh` result) | **173 ms** | 171 ms | 276 ms |
| plugin edition (live file) | **103 ms** | 97 ms | 116 ms |

**1.68× slower.** Answers are byte-identical (261/261), so this is pure regression risk.
→ On a **pristine tree**, `install.sh` produces a `MenuModel.js` without the guard work, so a
new install is slower than an existing one. **Correction (2026-10-21 16:47):** on *this* machine
the ranking patch is already applied, so `install.sh:138-139` takes the "already applied" branch
and the file is untouched — a re-run here is safe and would in fact repair the stale mirror
(see B11). The defect is that the pack cannot *reproduce* the plugin's file, not that it
regresses an already-patched tree.
→ Also: `uninstall.sh`'s `git checkout` path would wipe the guard work, and the pack can never
put it back.

**Fix:** ship `files/MenuModel.js` in the pack and `install -Dm644` it (like the plugin does),
or regenerate the patch to carry all three deltas.

### B2 · Emoji (and any astral-plane character) **cannot be typed into the filter**
`files/Menu.qml:2528`:
```js
} else if (text && Array.from(text).length === 1
```
and the comment directly above it claims:
> *Counted in CODE POINTS so a surrogate pair (emoji, one keypress on some layouts) is one
> character, not a refused length-2 string.*

**The comment is the opposite of the truth in QML's engine.** Measured:

| engine | `Array.from("😀").length` | `[..."😀"].length` |
|---|---|---|
| V8 / Node (standard ECMAScript) | 1 | 1 |
| **QML V4 (what the launcher runs in)** | **2** | **1** |

QML's `Array.from` on a string splits UTF-16 code units, exactly like `split("")`. So the
condition is false for every emoji, the key is **not typed and not consumed** — it leaks to the
focus chain (the same failure the code carefully avoids for Tab at `:2516-2521`).

**Fix:** one character — `Array.from(text).length` → `[...text].length` (verified working in QML).

### B3 · One trailing `//` comment in a menu file **silently empties the whole menu**
`MenuModel.js:1-5` (`stripJsonc`) only strips comments that occupy a whole line
(`/^\s*\/\/[^\n]*(\n|$)/gm`). Measured against this machine's real 344-entry default menu:

| input | entries parsed |
|---|---|
| as-is | **344** |
| one value changed to `"Go" // the Go menu` | **0** |
| one `/* block comment */` added | **0** |
| a `,` inside a string value | 344 (ok) |

A single trailing `//` makes `parseMenuJsonc` return `[]` → the **entire menu disappears**, with
**no error and no log line** (`Menu.qml:3593-3594` assigns the empty array and rebuilds).
A string value containing `,}` or `,]` also corrupts the file (the trailing-comma strip
`.replace(/,(\s*[}\]])/g,"$1")` runs inside string literals).

**This is upstream omarchy's own parser** — `git show HEAD:shell/plugins/menu/MenuModel.js` has the
byte-identical function — so the launcher inherits it. But the owner's own extension file carries
a hand-written warning about it (*"Parser rule: FULL-LINE comments only — trailing // breaks the
whole file"*), i.e. the limitation was known and worked around rather than fixed.

**Fix:** strip `//` comments only when outside a string literal, and support `/* … */`.
At minimum, log a warning when parsing yields 0 entries from a non-empty file.

### B4 · A partial user override **destroys** the default row it touches
`Menu.qml:455-457` says:
> *Merge defaults + user extension. Later entries override earlier ones on a per-key basis (so the
> user can tweak label/icon/action without re-declaring the whole row).*

**It is not per-key.** `normalizeItem` (`MenuModel.js:13-40`) always returns *every* field, filling
absent ones with defaults; `mergeMenuSources` (`MenuModel.js:66-96`) then copies *all* of the
user entry's keys over the default's.

Executed against the real default menu with a user file containing only
`{"system": {"aliases":["x"]}}`:

| field | default | after merge |
|---|---|---|
| `label` | `"System"` | **`"system"`** (the raw id) |
| `icon` | glyph | **`""`** |
| `action` | `omarchy-launch-webapp …` | **`""`** |
| `kind` | `action` | **`menu`** → a childless menu → **the row vanishes** |
| `when` / `checked` | guard expression | **`""`** → the guard is dropped |
| `aliases` | `["power-menu"]` | **replaced**, not appended → the default route alias stops resolving |
| `parent` | `"root"` | re-derived from the id |

Measured across the real menu: **260 of 344 default entries are altered** by the merge; **221 lose
their `action`**, **245 have their label collapse to the raw id**, **258 lose their icon**, **221
change kind `action`→`menu`**.

On this machine most of those are the `{"when":"false"}` hiding overrides, so the damage is
invisible today — but the *moment* such a row is re-shown it is an unlabelled, action-less husk,
and any partial override a user writes silently deletes the row.

**Also upstream's** (`normalizeItem`/`mergeMenuSources` are byte-identical to `821ae58`), and
**undocumented in both READMEs** — `grep -i "jsonc\|extension\|merge"` over both READMEs finds
only the unrelated phrase *"one merged block"*.

**Fix:** merge only the keys the user actually supplied (keep the raw entry, merge before
normalising); and document the rule in both READMEs.

### B5 · The calculator answers date-like queries with a **wrong number**
`Menu.qml:1088` auto-detects a calculation when the query has a digit and one of `+-*/%^`:
```js
if (/[0-9]/.test(q) && /[+\-*/%^(]/.test(q)) return q
```
`2026-10-21` → parses as `2026 - 10 - 21` → **1995**, and the answer row is shown at the top of
the results with the detail `2026-10-21 · Enter copies`. Verified in the live QML engine:
`classifyQuery("2026-10-21").mode === "calc"`, `calcEvaluate("2026-10-21") === 1995`.

The dedicated date tier (`isDateTimeQuery`) only recognises the literal words `date|today|time|now|heure`.

**Fix:** require a digit to be *adjacent* to an operator with no other digit in between
(e.g. reject when the query matches `^\d{4}-\d{2}-\d{2}$`), or require an explicit `=`.

### B6 · The `guardLine` id is interpolated into a shell script **unescaped**
`MenuModel.js:484-487`:
```js
return "if { " + substituteGuardReaders(expression) + "; } >/dev/null 2>&1; then echo "
  + id + ":" + tag + ":1; else echo " + id + ":" + tag + ":0; fi\n"
```
`id` comes from a JSONC key and is spliced raw. Measured with the id
`evil; touch /tmp/omarchy-audit/PWNED; #`:

```
if { true; } >/dev/null 2>&1; then echo evil; touch /tmp/omarchy-audit/PWNED; #:w:1; else ...
bash: -c: line 12: syntax error near unexpected token `}'
guard batch exit: 2   output: ""
```

The injection **does not execute** — bash refuses to parse the line. But the **entire guard batch
dies**, so every `when:`/`checked:`/`disabled:` in the menu goes unanswered. On a first run
`whenResults` is `{}`, `isVisible` only hides on an *explicit* `false`
(`MenuModel.js:257`), and therefore **every guarded row becomes visible** — including the ~230 rows
this machine deliberately hides.

A menu id containing `*` would additionally be glob-expanded by the unquoted `echo`.

**Fix:** `printf '%s:%s:1\n' <shell-quoted id> <tag>`.

### B7 · The 280 ms overlay hold leaks a fullscreen scrim into four other plugins
`files/OverlayWindow.qml` is **shared by 7 plugins**; the pack changed it globally, but only
`Menu.qml` was adapted to fade its own content. `Emojis.qml:166`, `Clipboard.qml:320`,
`ReminderFlow.qml:101` (`color: root.scrim`, 50 % alpha) and `wifiqr/Panel.qml:220`
(`Qt.rgba(0,0,0,0.78)`) have **no `opacity`/`visible` binding** and relied on `contentItem.visible`
going false the instant `shown` flips. With the 280 ms hold the surface stays fullscreen and
visible → the dimming scrim lingers ~280 ms after dismissing the emoji picker, clipboard history,
reminder flow or wifi-QR panel (a 78 %-black flash for wifi QR).

The pack's own comment at `files/OverlayWindow.qml:21-23` — *"Consumers that do not fade render
nothing in that window"* — is false for these four.

**Fix:** make the hold opt-in per consumer, or give the four scrim consumers their own fade.

### B8 · `uninstall.sh` does not reliably restore the pristine files
* `uninstall.sh:62` takes the snapshot branch whenever `BACKUP_KIND=pristine` **and** the snapshot
  contains `Menu.qml`; `restore_from_snapshot` (`:42-54`) only *warns* for files absent from the
  snapshot and leaves them as-is — the `git checkout` fallback at `:73` is never reached.
  **This is the live machine's state**: both existing snapshots contain only `Menu.qml` +
  `OverlayWindow.qml`; **running `./uninstall.sh` today leaves the ranking patch applied.**
* `uninstall.sh:73` uses `git checkout --`, which restores the **index**, not HEAD — a staged
  local edit survives the "restore the Omarchy checkout" path.

**Fix:** fall back to `git checkout HEAD -- <file>` per file for anything missing from the snapshot.

### B9 · `install.sh` has no rollback
`install.sh:125-128` has no `trap`. Repro: `chmod 555 omarchy/shell/Ui` → the script exits 1
right after `==> Installing files`, leaving `Menu.qml` replaced and `OverlayWindow.qml` untouched,
with only `install(1)`'s own stderr and no mention that a backup exists. The two files are
coupled (Menu's 200 ms fade depends on OverlayWindow's 280 ms hold) → a half-install yields a
launcher whose fade never plays.

### B10 · `install.sh` can take **no backup at all** while `MenuModel.js` carries a hand edit
`install.sh:51-67` (`PACK_STATE`) never inspects `$OMARCHY/shell/plugins/menu/MenuModel.js` — only
the *mirror's* copy (`:60`). The snapshot block (`:96-98`) is skipped when `PACK_STATE==1`
(`:89-91`). Repro: tree already at the pack revision + a hand-edited `MenuModel.js` → the script
prints *"Already at the pack revision — no new backup taken"* and **the backup root is never even
created**. The edit is then exposed to the ranking patch with nothing to restore it from —
contradicting the invariant stated in the script's own comment at `:46-50`.

`~/.local/share/omarchy/shell/plugins/menu/MenuModel.js` (18 Oct) = + the guard work.

### B12 · The Baloo "content" tier also matches **file names**, but is labelled "content"
`Menu.qml:1320` calls `baloosearch6 -l 24 <query>` with **no `-t`**. The default type is
`FileType` = name **or** content. Measured on this box:

```
$ baloosearch6 -l 5 "fix-round-plan"     → …/fix-round-plan-2026-10-20.md   (a NAME hit)
$ baloosearch6 -l 5 -t title "fix-round-plan" → (nothing)
```

Every row is then unconditionally labelled `content · …` (`Menu.qml:1362-1363`) and the README
says the query *"was found inside the file, not in its name"*. Partly masked in practice because
fd hits dedupe first (`:2055-2064`), but not guaranteed by the code.

**Fix:** pass `-t text` (KDE's `baloosearch6` accepts it) or rename the tier to "Baloo hits".

## Part 4 — Weaknesses & latent risks (not defects)

* **W1 — `searchScore` throws on a labelless entry** (`MenuModel.js:343`: `entry.label.toLowerCase()`).
  Not reachable today (every producer sets `label`), but one careless provider row crashes the
  whole search rebuild.
* **W2 — `searchScore` returns `NaN` when `entry.order` is missing** (`MenuModel.js:365`). `NaN`
  as a sort key makes the ordering engine-defined. `swapProviderRows` leaves `order` values
  **non-contiguous and duplicated** after a swap (measured `[0, 2, 2]`), so the `entry.order`
  tiebreak is unreliable between provider refreshes.
* **W3 — `depthFor` gives a direct child of `root` depth 0**, the same as `root` itself
  (`MenuModel.js:202` — the loop condition excludes `parent === "root"`). Coherent, but the name
  is misleading and the root's children and the root share a ranking tier.
* **W4 — link rows are looked up by `target` in `isVisible`/`childCount` but parented by `id`**,
  so a link with children would be invisible and report 0 children (`MenuModel.js:264-268`, `:382`).
  The real menu has **zero** `target` entries, so this is latent.
* **W5 — the guard batch runs under `bash -lc`** (`Menu.qml:3708`), a **login** shell: every guard
  evaluation sources the user's profile. The code compensates for `errexit`/`nounset` but the
  profile side-effects remain.
* **W6 — the guard readers are process substitutions that are never waited for**; a hung reader
  can outlive the batch.
* **W7 — `install.sh`'s dependency probe uses PATH, the runtime probe uses `/usr/bin` only**
  (`install.sh:33-44` vs `Menu.qml:3092-3096`). A tool in `/usr/local/bin` or a nix profile
  passes the install check but yields a **silently empty tier** at runtime. `files/ravi-window-focus:6`
  hardcodes `/usr/bin/hyprctl` for the same reason.
* **W8 — `install.sh:171` interpolates `$HOME` unescaped into a Hyprland lua string.**
* **W9 — `uninstall.sh:19` picks the newest snapshot with `ls -1 | sort -r | head -n1` over
  *all* entries, not just directories** — a stray file named e.g. `README` wins, `LATEST` becomes
  empty and the snapshot restore is silently skipped.
* **W10 — `uninstall.sh:88-96` decides rename-vs-delete by comparing against the *repo's* copy**
  of the helper, not against what was installed.
* **W11 — `uninstall.sh:44`'s `cp` preserves the destination's mode**; the snapshot path does not
  restore file modes (the git path does).
* **W12 — mirror restore asymmetry**: `install.sh:156` mirrors `OverlayWindow.qml` only if
  `$MIRROR/Ui` exists, `uninstall.sh:119` copies into it unconditionally → spurious warning; and
  `uninstall.sh:110` skips the whole mirror block when `$MIRROR/plugins/menu` is missing.
* **W13 — the 280 ms hold keeps the surface on the Overlay layer**, breaking upstream's own
  documented invariant *"off the overlay layer so it never blocks direct scanout"* — a
  fullscreen transparent layer-shell surface blocks direct scanout while it is up.
* **W14 — the 280 ms hold and the 200 ms fade are two magic constants in two files** with no
  shared value or assertion; retiming one silently clips the other.
* **W15 — `patch --forward` fallback (`install.sh:140-144`) is not atomic** (unlike `git apply`):
  a partial application leaves `.rej`/`.orig` files inside the omarchy tree.
* **W16 — `finishRequest`'s `activeSelectionFile === ""` guard** (`:347`) does not cover
  `undefined`, which still yields `> ''` and a runtime failure.
* **W17 — snapshots accumulate forever**; `install.sh` never prunes the backup root.
* **W18 — `slashify` is lossy for non-ASCII**: `"Café Münch"` → `"caf-m-nch"`, `"Über"` → `"ber"`.

## Part 5 — What is verified **correct**

I checked these because they are the parts most likely to be quietly wrong; all pass.

**Arithmetic & answers** (real Qt6 QML engine, the launcher's own functions):
`1+2→3 · 2*3→6 · 10/4→2.5 · 2^10→1024 · 7%3→1 · 1+2*3→7 · (1+2)*3→9 · -2^2→-4 · 2^3^2→512 ·
1/0→no answer · 0/0→no answer · sqrt(16)→4 · abs(-3)→3 · min(2,9)→2 · max(2,9)→9 ·
round/floor/ceil · pi/e/tau · log(100)→2 · ln(1)→0 · 1+ →no answer · *2 →no answer ·
(1+2 →no answer · 1..2 →no answer · hello →no answer · sqrt(-1)→no answer · asin(2)→no answer ·
64 nested parens→1 (budget) · 65→no answer · 200→no answer (no stack overflow)`.

**Unit conversion** (25 cases): SI+IEC bytes (`1 gb in mib`→953.674, `1 kib in bytes`→1024),
length (`1 mi in km`→1.609344, `1 in in cm`→2.54), mass (`1 lb in kg`→0.45359237), time
(`1 day in h`→24), speed (`100 kmh in mph`→62.137), temperature (`0 c in f`→32, `100 c in f`→212,
`32 f in c`→0, `-10 c in f`→14 ✓, `0 c in k`→273.15, `300 k in c`→26.85), exponents (`1e9 b in gb`→1),
plurals (`5 pounds in kg`→2.26796185). Cross-category pairs correctly convert nothing.

**Colour**: `#ff0000`→`#ff0000`/rgb(255,0,0)/hsl(0,100%,50%); `#f00` expands; `#ff000080`→
`rgba(255,0,0,0.5)`; uppercase normalised; 5-digit, no-hash and non-hex rejected; `hexToColor`
expands both 3- and 4-digit forms (Qt's own `#AARRGGBB` order is handled).

**XML/XBEL/bookmarks**: `&#x41;`/`&#65;`/`&lt;&gt;&quot;&apos;&amp;` decode exactly once
(`&amp;lt;` → `&lt;`, **not** `<`); out-of-range and surrogate code points are dropped, not thrown;
percent-decoding happens **after** XML unescaping; a newline inside a path drops the entry;
`/Trash/` excluded; GTK bookmarks parse with labels, skip `smb://`, and dedupe.

**Frecency**: decay to zero over 30 days, cap at 10 hits / 250 boost, `adoptFrecency` rejects
non-object records, non-numeric `c`, negative `c`, null records and coerces a bad `t` to 0;
garbage JSON → empty set, never a throw.

**Window tier**: scratchpad and negative-workspace exclusion, `mapped === false` exclusion,
address required, malformed JSON → empty, boost → workspace → title → address ordering, 8-row cap.

**File tier**: trailing `/` stripped (or the basename parses empty and the row is dropped),
`/home/ravi2` never shortened to `~2`, exact/prefix/substring scoring, depth clamped at 20.

**Shell-inert query token**: `encodeURIComponent` + `!'()*~` leaves only `[A-Za-z0-9-_.%]`;
`$(whoami)`, backticks, `;`, `|`, `&`, quotes and globs are all neutralised.

**Key tree** (42 assertions): Backspace edits / with an empty filter goes back, Escape clears then
cancels, Ctrl+U clears, **Ctrl+C and Super+C are reachable** (upstream's `Util.editsFilter`
only claims Backspace and Ctrl+U, so the chords are not swallowed), Ctrl+V and Shift+Insert,
Ctrl+Alt+letter refused but **Alt+letter typed** (AltGr), function keys not consumed, Tab and
Shift+Tab always consumed, surrogate-pair handling (→ B2).

**Selection model** (14 assertions): disabled rows skipped in both directions, wrapping, `-1` when
every row is disabled, `settleCursor` parks on 0 and leaves the cursor inactive.

**Provider merge**: ids slugified, colliding ids nudged (`fira-code`, `fira-code-`), the current
value gets `✓`, the provider icon otherwise, `action` from `actionFor`, `providerMenu` stamped, and
a second swap **replaces** the provider's previous rows (no duplicates).

**Guard batch, live** against this machine's real menu: 261 guarded items → **261 output lines,
0 malformed, 0 unanswered**, every one of the owner's `{"when":"false"}` rows correctly `false`.
**198 ms cold / 108 ms warm.**

**Capability probe**: `/usr/bin`-only for tier tools, PATH for openers and file managers, `fm=`
answered by name, openers reported missing only when all three are gone, a file manager is
deliberately *not* in the "missing" list.

**`install.sh` / `uninstall.sh`, live cycle** in a sandbox: `bash -n` clean; install backs up,
installs, applies the patch, syncs the mirror and preserves a differing user helper in the
snapshot; re-run is idempotent; uninstall restores all three files **byte-for-byte** to HEAD
(`sha256sum -c` → 3/3 OK, `git status` clean) and re-syncs the mirror.

**Patches**: both `menu-model-ranking.patch` and `omarchy-launcher-v2.patch` apply **cleanly** to
pristine `821ae58` (`git apply --check` rc=0); the big patch reproduces `files/Menu.qml` and
`files/OverlayWindow.qml` **byte-identically**; on the live tree the ranking patch correctly
detects "already applied" (reverse-check rc=0).

**Plugin packaging**: `omarchy plugin validate .` → rc=0; the manifest is schema-valid; the plugin
is genuinely loadable as a second menu (`shell.qml` injects `omarchyPath`/`shell`/`manifest` into
a menu-kind plugin and gives it the `appLibrary` API), so the Apps provider and app
launch/uninstall are **not** broken in plugin mode.
